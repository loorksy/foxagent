# خطة تطوير قدرات وكيل FoxAgent

> وثيقة تنفيذ. لا تُنفَّذ مرحلة قبل إغلاق اختبارات المرحلة السابقة.
> المرجعان: OpenClaw (أدوات/مهارات/كرون/لوحة حيّة) و
> [TencentCloud/TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory)
> (هرم ذاكرة L0–L3 + Skill + Wiki + Code-Graph).
> القواعد المقدسة لا تُمس: ذهب فقط (XAU_USD) · بوابة المخاطر تُشدَّد ولا تُرخى ·
> Pause يوقف كل شيء بما فيها الكرون والتصفح والتنفيذ · أوامر الوساطة عبر بوت تنفيذ + MT5 فقط ·
> لا `eval`/`exec` في عملية الخادم · لا أخبار مخترعة.

---

## 0. الهدف

تحويل FoxAgent من طاقم ثابت (فني → ماكرو → نقاش → مخاطر) يردّ عند السؤال، إلى
**حارس مكتب ذهب**: يتصفح مصادر مسموحة، يطلق وكلاء فرعيين بمهمة واضحة، يتعلّم مهارة
بعد كل صفقة، يجدول عملاً على **كل الجلسات** (آسيا / لندن / نيويورك / التداخلات)،
يرسم على الشارت بفأرة حقيقية بعد أن يرى البكسلات، ويعرض لوحة حيّة داخل المحادثة
لا تختفي عند إغلاق اللوحة الجانبية.

المحرك المعرفي الإلزامي للوكيل (وليس برومبتاً زينة): الذهب أصل بلا عائد (zero-yield)،
ملاذ آمن، وأداة تحوط. أي تحليل ماكرو أو خبر أو توصية يمر على شبكة المحركات أدناه
ويربطها بشاشتين لحظيتين: **DXY** و**US10Y / العائد الحقيقي 10Y TIPS**.

## 1. عقد المعرفة — محركات الذهب (Wiki إلزامي)

يُخزَّن كنسخة Wiki ثابتة (`gold_drivers`) يقرأها الوكيل بأداة `wiki_read` قبل أي
تحليل ماكرو أو توصية. ممنوع اختراع رقم أو نبرة فيدرالي أو تدفق ETF إن كانت الأداة فارغة.

### 1.1 السياسة النقدية والعوائد (الأقوى)
- عوائد الخزانة الحقيقية (US Real Yields / 10Y TIPS): ارتباط عكسي. ارتفاع العائد الحقيقي
  = تكلفة فرصة أعلى لحيازة الذهب = ضغط هبوطي. العكس صحيح.
- FOMC + المؤتمر الصحفي: نبرة Dovish تدعم الصعود، Hawkish أو «higher for longer» تضغط.
- Dot Plot: يحدد الاتجاه المتوسط/الطويل.
- DXY: الذهب مقوَّم بالدولار. قوة الدولار تقلّل الطلب لحظياً (عكسي)، إلا في الحروب
  حيث قد يرتفع الاثنان معاً.

### 1.2 البيانات الأمريكية (توقعات الفائدة)
- NFP + البطالة: قوي = تشدد محتمل = سلبي لحظي للذهب. ضعيف = صعود فوري.
- CPI و Core PCE: أعلى من المتوقع = هبوط لحظي (تأخير التيسير) وقد يدعم الذهب لاحقاً
  كتحوط تضخم. أقل من المتوقع = صعود سريع.
- PPI + مبيعات التجزئة: استباقي للتضخم وقوة المستهلك.

### 1.3 جيوسياسة وأزمات
- حروب ونزاعات مباشرة: قفزات مفاجئة، وقد ينكسر العكس مع الدولار.
- أزمات مصارف / ديون سيادية: هروب من المخاطر إلى الذهب.
- عقوبات وحروب تجارية: طلب احتياطي (إزالة دولرة).

### 1.4 مشتريات البنوك المركزية (هيكلي)
- PBOC وغيره: زيادة الاحتياطي الشهرية = أرضية تمنع الانهيارات الكبيرة.
- تقارير WGC الربعية: تدفقات العرض/الطلب وإزالة الدولرة.

### 1.5 المؤسسات والمشاعر
- COT (CFTC كل جمعة): صافي مراكز Managed Money — تشبع شراء/بيع.
- Gold ETFs وأبرزها GLD: تدفقات الدخول = استثمار مؤسسي طويل.

### 1.6 الطلب المادي والموسمي
- الهند: موسم الأعراس + ديوالي (أكتوبر/نوفمبر).
- الصين: رأس السنة القمرية (يناير/فبراير).
- جمارك سويسرا/بريطانيا: تسييل أو تجميع سبائك.

### 1.7 قاعدة التزامن اللحظي
عند صدور خبر قوي يراقب الوكيل **دائماً** ثلاث شاشات معاً: سعر XAU_USD + DXY + US10Y
(ويفضّل 10Y TIPS إن توفّر). إن هبط DXY وUS10Y معاً بحدة → أقوى موجات الصعود اللحظية
للذهب. لا توصية لحظة خبر بدون هذه الثلاثية إن كانت الأدوات قادرة على جلبها.

### 1.8 الجلسات — كلها، بلا افتراض لندن
| مفتاح | النافذة (UTC) | ماذا يفعل الحارس |
|---|---|---|
| `asian` | 00:00–08:00 | مسح مدى آسيا، سيولة، تحضير لندن |
| `london` | 07:00–16:00 | كسر/إعادة اختبار مدى آسيا، أول موجة |
| `london_ny` | 12:00–16:00 | تداخل — أعلى سيولة |
| `ny` | 12:00–21:00 | أخبار أمريكية، إغلاق يومي |
| `sydney` | 21:00–06:00 | افتتاح خفيف، ترحيل |

الكرون والقلب النابض يُعلَّمان على هذه المفاتيح صراحة. لا قيمة افتراضية `london`.
إن لم يحدد المستخدم جلسة، يُجدول على **الجلسة الجارية حسب UTC** وكل الجلسات التالية
المطلوبة للمهمة (مثلاً «احرس اليوم» = الآسيوية ثم لندن ثم التداخل ثم نيويورك).

## 2. الذاكرة — اقتباس TencentDB-Agent-Memory داخل FoxAgent

لا نُدخل خدمة Tencent السحابية كاعتماد تشغيل. نقتبس **النموذج** وننفّذه محلياً
(SQLite/Postgres الحالي + فهارس). أربعة أصول ذاكرة، هرم L0–L3:

| الأصل | المعنى في FoxAgent | متى يُكتب |
|---|---|---|
| **Chat Memory (L0→L3)** | L0 حوار خام · L1 ذرات (حقيقة/قيد/تفضيل) · L2 سيناريو (NFP، تداخل لندن-نيويورك، FVG غير مُخفَّف) · L3 شخصية المكتب (أسلوب المشغّل، عتباته) | كل جولة + نهاية الجلسة |
| **Skill** | SOP قابل لإعادة الاستدعاء: «ما قبل NFP»، «لا تدخل نيويورك قبل دقيقة من الخبر»، «ارسم سيولة آسيا قبل لندن» | بعد صفقة مغلقة (TP/SL/انتهاء) أو بعد مهمة فرعية نجحت |
| **Wiki** | المعرفة الثابتة: محركات الذهب §1 + تشغيل المكتب + عقد التوصية | يدوي + مراجعة بشرية؛ الوكيل يقرأ ولا يعيد كتابة المحركات إلا بمسودة |
| **Code-Graph** | رموز استراتيجيات Python في المكتبة: `on_bar`، الاعتماديات، أثر تعديل استراتيجية على البوتات | عند حفظ/فحص استراتيجية كود |

### 2.1 خط الأنابيب بعد كل صفقة (تعلّم منظّم)
1. إغلاق التوصية (TP1/TP2/SL/انتهاء) يطلق مهمة `reflect`.
2. وكيل فرعي `LessonExtractor` يقرأ L0 للصفقة + النتيجة + سياق الجلسة والخبر.
3. يُستخرج: ذرة L1 واحدة على الأقل + مسودة Skill إن تكرّر النمط مرتين.
4. المسودة `status=draft` — لا تُثبَّت في البرومبت إلا بعد موافقة المشغّل (أو عتبة نجاح
   واضحة في الباك تست إن كانت المهارة استراتيجية).
5. الاسترجاع: الجولة الجديدة تبدأ من L3+L2+المهارات المثبّتة، وتنزل إلى L1/L0 عند الحاجة فقط
   (لا حقن السجل كاملاً).

### 2.2 أدوات الذاكرة (يكتشفها الوكيل عبر Tool Search)
`memory_recall` · `memory_capture` · `skill_search` · `skill_read` · `skill_propose` ·
`wiki_read` · `wiki_search` · `codegraph_impact`

## 3. Tool Search بدل إرسال كل الأدوات

اليوم تُرسل مواصفات ~18 أداة في كل جولة. بعد الخطة:

1. البرومبت الأساسي يرى **فهرساً قصيراً** (اسم + سطر واحد + وسم).
2. الأداة `tool_search(query)` تُرجع 3–8 أدوات مناسبة مع المخطط الكامل.
3. `tool_describe(name)` لواحدة.
4. نواة دائمة (لا تُخفى): `tool_search`، `spawn_subagent`، `memory_recall`،
   `wiki_read`، `get_live_price`، `raise_if_paused`.
5. أدوات التنفيذ (`place` عبر MetaApi) تبقى غير مرئية إلا لبوت التنفيذ وبعد MT5.

## 4. وكلاء فرعيون بمهمة واضحة

الطاقم الثابت يبقى **قالباً اختيارياً** لنوايا `recommendation` فقط. لباقي النوايا
والهام الحارس: الوكيل الأب يفوّض.

```
spawn_subagent({
  goal: "اجمع أخبار ساعتين واربطها بـ DXY وUS10Y",
  budget: { max_rounds: 6, max_seconds: 90, max_usd: 0.15 },
  tools: "search" | ["web_fetch", "get_economic_calendar", "wiki_read"],
  output: "brief" | "table" | "overlays" | "skill_draft"
})
```

قواعد:
- الابن لا يرى أدوات الأب كلها؛ فقط ما سُمح له + النواة الآمنة.
- الابن لا يستدعي `send_recommendation` ولا يضع أوامر.
- عند انتهاء الميزانية يُعاد ملخص أو فشل صريح.
- الأب يجمع النتائج ويتكلم بصوت FoxAgent الواحد.
- أمثلة تفويض: جمع أخبار · مقارنة ≤3 استراتيجيات في المستودع · مسح الجلسة الجارية ·
  استخراج مهارة بعد صفقة · رسم هيكل على الشارت ثم التحقق بالصورة.

## 5. تصفح الإنترنت (متصفح محصور، ليس exfil للخادم)

### 5.1 طبقتان
- `web_search(q)` و`web_fetch(url)`: بحث وجلب نص مقروء.
- `browser_*`: جلسة كروم معزولة (Playwright) للصفحات التي تحتاج تنفيذاً: تنقل، لقطة،
  استخراج نص مرئي. ليست طرفية على الخادم (`exec` ممنوع).

### 5.2 قائمة سماح (تُوسَّع من الإعدادات، ذهب فقط)
Forex Factory · Investing (تقويم + DXY + US10Y) · Reuters/Bloomberg للعناوين ·
CFTC COT · World Gold Council · GLD/SPDR flows · مواقع جمارك/تقارير بنوك مركزية
معروفة · صفحة OANDA العامة عند الحاجة. أي نطاق خارج القائمة = رفض مغلق.

### 5.3 عقد الصدق
الأداة الفارغة أو المحظورة تُرجع `unavailable` — الوكيل يقول ذلك ولا يخترع NFP/CPI/FOMC.
كل خبر يُربط بأحد بنود §1 (عائد حقيقي، DXY، ملاذ، بنك مركزي، COT، ETF، موسمي).

## 6. Computer Use حقيقي على الشارت

ليس مؤشراً مزيّفاً يتحرّك بعد JSON.

1. الوكيل يطلب `chart.screenshot` فيُلتقط الكانفس الحي (ما يراه المشغّل).
2. تُرسل الصورة إلى النموذج مع أداة حاسوب: `mouse_move`، `left_click`، `drag`،
   `screenshot` ضمن إطار الشارت فقط (إحداثيات بكسل → زمن/سعر عبر `convertFromPixel`).
3. كل سحب يُترجم إلى overlay حقيقي (خط اتجاه، مستطيل FVG، خط سعر، فيبوناتشي، نص).
4. بعد كل ضربة: لقطة جديدة تُعاد للوكيل وللمحادثة. إن أخطأ الخط يعيد السحب.
5. الرسوم تُحفظ في حالة الجلسة + اللوحة الحيّة حتى لو أُغلقت اللوحة الجانبية.

البيئة: إطار الشارت في الواجهة (وأخت اختيارية headless لنفس المحرّك). لا سطح مكتب
كامل ولا نقر خارج المكتب. Pause يلغي أي حلقة فأرة فوراً.

## 7. جدولة من الشات + قلب نابض (كل الجلسات)

من المحادثة، لغة طبيعية → مهمة مخزّنة:

| مثال المستخدم | الترجمة |
|---|---|
| كل يوم 8 صباحاً حلّل | `cron` يومي 08:00 بتوقيت المكتب، نية `analysis`، الجلسة الجارية + التالية |
| كل بداية لندن امسح M15 | `session_open:london` + `structure_scan` M15 |
| كل بداية آسيا / نيويورك | نفس العقد على `asian` / `ny` |
| قبل الخبر بـ 30 دقيقة جهّز البطاقة | ربط بحدث تقويم (NFP/CPI/FOMC/PCE) − 30 د |
| إذا تغيّر الهيكل نبّه تيليجرام | `heartbeat` يقارن آخر مسح؛ عند BOS/كسر مدى يُرسل تنبيه |

القلب النابض (heartbeat): دورة قصيرة (مثلاً 60–180 ث) طالما المكتب غير متوقف:
سعر · هيكل الإطار النشط · الثلاثية XAU+DXY+US10Y قرب الأخبار · مهام الكرون المستحقة.
لا حلقة أثناء Pause. لا توصية تلقائية تتجاوز بوابة المخاطر. التنفيذ يبقى على بوت
التنفيذ + موافقة إن لزم.

تخزين: جدول `agent_jobs` (id، عبارة المستخدم، جدول زمني أو مفتاح جلسة أو حدث،
نية، حمولة، آخر تشغيل، حالة). الواجهة: قائمة مهام الحارس في الدردشة أو الإعدادات.

## 8. لوحة حيّة داخل المحادثة (Canvas)

بطاقة ثابتة في خيط الشات (ليست اللوحة الجانبية):

- شارت مصغّر حي + overlays الحالية
- مستويات: دخول / وقف / TP إن وُجدت توصية
- ساعة الجلسات الأربع + التداخل (الجلسة الجارية مظلّلة)
- الثلاثية اللحظية: XAU · DXY · US10Y (و TIPS إن وُجد)
- التقويم: الأحداث القادمة عالية الأثر فقط
- آخر مهارة/درس مُسترجع

الوكيل يخاطب اللوحة بأدوات: `canvas.set_focus`، `canvas.draw`، `canvas.set_levels`،
`canvas.highlight_event`. إغلاق الشارت الجانبي لا يمسح اللوحة ولا الرسوم.

## 9. مراحل التنفيذ

### المرحلة A — Wiki المحركات + عقد الجلسات
- ملف/جدول `gold_drivers` + أداة `wiki_read`.
- ساعة جلسات بأربعة مفاتيح + تداخل، بلا افتراض لندن.
- ربط التقويم الحالي بوسوم المحركات (fomc، nfp، cpi، pce، cot، …).
- اختبارات: الوكيل لا يخترع حدثاً إن فارغ؛ تصنيف خبر → وسم محرّك.

### المرحلة B — ذاكرة Tencent-style
- جداول L0–L3، skills، wiki، codegraph_symbols.
- خط `reflect` بعد إغلاق الصفقة → ذرة + مسودة مهارة.
- استرجاع يبدأ من L2/L3 + المهارات المثبتة.
- اختبارات استخراج/استرجاع/عدم تثبيت مسودة تلقائياً.

### المرحلة C — Tool Search + تفويض فرعي
- فهرس أدوات + `tool_search` / `tool_describe`.
- `spawn_subagent` مع هدف وميزانية وعقد إخراج.
- نية `recommendation` يمكنها استخدام القالب القديم أو التفويض.
- اختبارات: الابن لا يوصي ولا ينفّذ؛ انتهاء الميزانية يوقف.

### المرحلة D — ويب ومتصفح مسموح
- `web_search` / `web_fetch` + Playwright معزول + قائمة سماح.
- مصادر إلزامية عند التوصية قرب خبر: التقويم + محاولة DXY + US10Y.
- اختبارات: نطاق مرفوض يفشل مغلقاً؛ انقطاع المصدر = `unavailable`.

### المرحلة E — Computer Use على الشارت
- لقطة كانفس حي، حلقة فأرة→overlay→لقطة تحقق.
- إظهار اللقطة في المحادثة + استمرار overlays.
- اختبارات إسقاط بكسل↔سعر/زمن؛ Pause يقطع الحلقة.

### المرحلة F — كرون + قلب نابض لكل الجلسات
- تحليل عبارة الجدولة من الشات.
- مشغّل `session_open` للآسيوية/لندن/التداخل/نيويورك/سيدني.
- قلب نابض + تيليجرام عند تغيّر هيكل أو اقتراب خبر.
- اختبارات: Pause يجمّد الوظائف؛ لا وظيفة «لندن فقط» كافتراضي.

### المرحلة G — اللوحة الحيّة في الشات
- مكوّن Canvas داخل الفقاعة/الخيط.
- مزامنة overlays والمستويات والتقويم والثلاثية.
- اختبارات: إغلاق اللوحة الجانبية يُبقي اللوحة والرسوم.

### المرحلة H — دمج ومراجعة ونشر
- pytest + vitest + tsc + lint.
- مراجعة مقدسة (fox-sacred-review) مع التعديلات المعتمدة.
- دمج على `main` ثم بناء حاويات الـ VPS والتحقق من الصحة.

## 11. مخاطر وحدود صريحة

- المتصفح = قائمة سماح + عزل. لا `exec` على الخادم.
- Computer Use داخل إطار الشارت فقط.
- المهارات المستخرجة مسودة حتى اعتماد بشري.
- الكرون لا يتجاوز Pause ولا بوابة المخاطر ولا الذهب.
- DXY/US10Y إن تعذّر جلبهما: يذكر الوكيل النقص ولا يختلق المنحدر.
- لا نضيف واتساب/سلاك في هذه الخطة؛ تيليجرام للتنبيه وأوامر الحارس فقط.

## 12. تعريف الإنجاز

المشرف يكتب: «كل بداية آسيا وجميع الجلسات امسح M15 ونبّهني إن تغيّر الهيكل،
وقبل NFP بـ 30 دقيقة جهّز البطاقة». المكتب يجدول على الآسيوية ولندن والتداخل
ونيويورك دون افتراض لندن، يطلق فرعياً لجمع الخبر وربطه بـ DXY/US10Y، يرسم على
الشارت بعد رؤية اللقطة، يظهر اللوحة داخل الشات، وبعد إغلاق الصفقة يقترح مهارة
مسودة. Pause يوقف الكرون والمتصفح والفأرة والتنفيذ فوراً.
